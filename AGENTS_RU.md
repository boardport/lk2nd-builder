# Паспорт проекта и регламент для AI-ассистентов: lk2nd Builder

> **Проект:** BoardPort — lk2nd Builder  
> **Организация:** [BoardPort](https://github.com/boardport) | **Репозиторий:** `boardport/lk2nd-builder`  
> **Миссия:** Модульный сборщик модифицированных образов загрузчиков lk2nd/lk1st на основе оверлеев  
> **Целевая экосистема:** Встраиваемые аппаратные платформы, 4G/LTE-модемы и мобильные устройства | **Лицензия:** [MIT](./LICENSE)  

---

## 1. Организация контекста AI

Корневые файлы [`AGENTS.md`](./AGENTS.md) и [`AGENTS_RU.md`](./AGENTS_RU.md) служат базовым регламентом для всех AI-ассистентов.
Разработчики изолируют и настраивают вторичный контекст под свои конкретные инструменты:

- **Специализированные каталоги (`.(gemini|claude|cursor|continue|qwen|etc)/`):** Индивидуальный контекст конкретного ассистента
  (промпты, скиллы, отчеты, логи сессий). Данные каталоги изолированы и исключены из индексации git (`.gitignore`).
- **Файлы маршрутизации контекста:** Навигация и индексация внутри специализированных каталогов организована через
  `.{ai}/README(_RU).md` или `.{ai}/AGENTS(_RU).md`. Инструкции дополняют корневой регламент и имеют приоритет внутри своего контекста.
- **Файл `.aiignore`:** Определяет ресурсы, строго исключенные из фоновой индексации и сканирования
  (деревья исходников, дампы, скомпилированные образы, временные кэши). Агенты обращаются к ним только по прямому указанию пользователя.

## 2. Архитектура и организация подмодулей

- **Репозиторий-оркестратор:** `boardport/lk2nd-builder` координирует сборочные окружения и слои кастомизации.
- **Слои подмодулей:**
  - `docker/` (`boardport/lk2nd-docker`): Рецепты сборки контейнеров (`toolbox`, `toolchain`),
    Dockerfile и определения кросс-компиляционного окружения.
  - `overlay/` (`boardport/lk2nd-overlay`): Внешний аппаратно-зависимый оверлей (профили таргетов, файлы DTS,
    патчи загрузчика и аппаратные адаптации).
- **Чистота Git:** Исходные деревья апстрима (`/lk2nd*`, `/littlekernel*`), локальные рабочие копии,
  готовые бинарные образы (`output/`, `volumes/output/`) и временные файлы (`tmp/`, `volumes/tmp/`) никогда не отслеживаются в системе контроля версий.

## 3. Инструментарий автоматизации (Makefile)

Проект включает корневой оркестратор `Makefile` и модульные задачи в `.make/`:

- `make help` / `make list`: Просмотр всех доступных команд автоматизации.
- Конкретные цели импортируются из модулей `.make/*.mk`.
- **Правило корневого Makefile:** Категорически запрещено добавлять новые команды непосредственно
  в корневой `Makefile`. Все цели размещаются в файлах `*.mk`.

Подробная техническая документация расположена в каталоге `docs/` (`docs/overview.ru.md`, `docs/architecture.ru.md`, `docs/development.ru.md`).
Документация подмодулей доступна в `docker/README_RU.md` и `overlay/README_RU.md`.

## 4. Стандарты документации Markdown

- **Правила форматирования:** Синтаксис и стилистика регулируются файлами `.editorconfig` и `.markdownlint-cli2.jsonc`.
- **Обязательная проверка линтером:** Выполните команду `npx markdownlint-cli2 "**/*.md"` (перед завершением работы должно быть `0 issues in 0 files`).
- **Зеркальная двуязычность:** Вся публичная документация ведется параллельно (`*.md` на английском и `*_RU.md` на русском).

## 5. Стандарты Git и GitHub (`.github/`)

- Организационные политики, шаблоны issue, описания PR и CI-пайплайны находятся в каталоге [`.github/`](./.github/).
- Стандарты сообщений коммитов следуют спецификации Conventional Commits (например, `feat:`, `fix:`, `docs:`, `chore:`).
- **Правило Git-коммитов:** Создание Git-коммитов разрешено **только по прямому подтверждению пользователя**.
